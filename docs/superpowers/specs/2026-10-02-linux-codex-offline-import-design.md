# Linux Codex CLI Offline Pet Import — Design

## Scope and evidence

This Linux-only implementation imports pets that the installed **Codex CLI** has already materialized on disk. It supersedes the implementation scope of `2026-10-02-installed-pets-and-chatgpt-profile-design.md` and its plan on this branch; that larger design is retained as deferred research, not authorization to implement its desktop/linked pieces. The owner chose CLI custom pets, legacy avatars, and locally cached built-ins. No manual export or source path is needed. Existing ZIP/directory import, managed library, bundled Pi, global selection, `/pet-create`, and normal export behavior remain intact.

The pinned CLI source revision, paths, manifest fields, cache filenames, default animation mapping and Linux desktop investigation are recorded in `docs/superpowers/references/2026-10-02-pet-source-formats.md`. The logged-in official ChatGPT Desktop displayed account pets but did not materialize pet-specific manifests/assets or establish a readable local authoritative selection. Therefore **no ChatGPT Desktop or Codex App discovery, account/cloud pet download, linked profile, shared-setting reader, OAuth gate, or macOS/Windows adapter** is included. Do not expose a nonfunctional linked profile. Only documented CLI files are valid discovery inputs; Pi never starts Codex, logs into another app, calls internal account APIs or downloads absent assets.

## User experience

`/pet-import-source` opens a picker of installed Codex CLI pets. `/pet-import-source codex-cli` is equivalent; other arguments explain the Linux-only supported source. Each row shows the display name, category (custom/legacy/built-in), and availability of its local spritesheet. If `CODEX_HOME` is absent, use the CLI's documented Linux default `~/.codex`; do not recursively search unrelated homes. Missing CLI storage produces an actionable message. Built-ins without cached spritesheets appear in the list but cannot be imported until the owning CLI caches them; Pi neither downloads nor invokes Codex. List only catalog built-ins documented at the pinned revision; do not infer additional files by extension/name. A directory with an unsupported manifest shape or unsafe asset is unavailable with a concise reason, without breaking other choices; the pinned CLI manifest has no mandatory version field.

Selecting a locally available pet snapshots and validates the source, normalizes it into portable frames, and offers the existing case-insensitive name collision confirmation. A successful import creates an independent managed copy in the global library, announces its ID and `/pet-switch` instruction, and **does not change selection**. Cancel/stale-session paths produce no managed entry. Imported copies remain usable after source removal. `/pet-list`, `/pet-switch`, and `/pet-export` work with imported pets as with existing packages. CLI's local `tui.pet` is not read or followed; this feature is import-once, not sync. No owner pet names/artwork appear in repository fixtures, documentation, or npm contents.

## Format and normalization

Recognize documented `CODEX_HOME/pets/<id>/pet.json`, `CODEX_HOME/avatars/<id>/avatar.json` and the versioned built-in asset cache under `CODEX_HOME/cache/tui-pets/v1/assets`. Read only a recognized manifest plus its declared child spritesheet, or an exact cached built-in spritesheet filename from the pinned catalog. An ordinary on-disk `pet.json` is not a portable Pi pet ZIP; it must go through this source adapter. Use verified CLI geometry (192×208 cells, 8 columns and 9 rows by default), custom frame/grid metadata only when valid, and named animation tracks from the source implementation. The supported normalized cell is always 192×208; reject unsupported geometry, unexpected grid dimensions, invalid indices, nonfinite FPS or undefined fallback references rather than guessing rows/resizing. Require idle; absent optional states explicitly reuse idle and disclose that fallback in the import result. Keep original track order and repetitions; Pi's configured frame period, not native FPS, controls playback.

PNG and WebP spritesheets only. A bounded decoder checks the compressed format, declared and actual dimensions and pixel count **before full decode**, rejects animated/multipage or malformed content, decodes one sheet at a time, slices source cells to 192×208 transparent PNGs, and validates the resulting Pi frames. Use a lazily loaded native decoder to keep unrelated bundled/previously imported pets usable if that optional platform binary is unavailable. Bounds: 256 candidate pets per source, 64 KiB per manifest, 16 MiB compressed spritesheet, 16 million decoded pixels, no more than 256 source cells and no more than 256 normalized frames. Treat mid-read source replacement as a failed snapshot, never mix metadata and artwork from different revisions. Discovery must not allocate/decode the images of all listed pets.

Create **portable normalized schema version 2** for variable state-track lengths: the same seven Pi states, canonical `<state>/<nn>.png` paths, SHA-256 per frame, 1–256 frames per state and <=256 normalized frames across all states. Keep schema version 1 strict with its current fixed frame counts. Existing original-export inputs stay strict and backward compatible. Rendering and controller indexing use the actual selected animation length; replacing artwork must not reset activity/configuration/visibility. Output exported ZIPs contain only canonical normalized frames, manifest and harmless metadata, never the source directory, account data, proprietary original spritesheets or source provenance.

## Safety and lifecycle

Directory entries, manifest-relative spritesheet paths, and selected assets cannot escape the documented Codex root through traversal, links or changed paths. Bound JSON and file reads; reject symlinks and unusual file types. Use an opaque discovered candidate key; user-provided command arguments never become filesystem paths. Selection and import work only with interactive TUI context, guarded by the current session/generation. The source snapshot is immutable during normalization, and revalidate its identity after a read; a stale dialog cannot install under a new session.

Reuse `PetLibrary.install()`'s exclusive mutation reservation and collision checks. Record the owning local source directory and the selected manifest/artwork locations as **local-only provenance**; retain provenance on replacement and recheck export destination protection inside the existing final export mutation reservation. Since existing source metadata accepts `zip` or `directory` based on filesystem type, file-sourced built-ins should record the exact asset file; source protection must not rely on a `.zip` suffix. Never export onto a source asset/manifest, within a protected source directory, into the managed library, or into bundled Pi. Source metadata stays outside portable ZIPs. Do not distribute copyrighted OpenAI/third-party pet artwork or claim a license; owner-controlled local copies only.

No background monitor, polling, login, credential access, or new timer is added. Unsupported runtime/platform/decoder errors stay isolated to `/pet-import-source`. Existing text fallback for broken bundled artwork and prior before-settle abort-outcome limitation remain unchanged.

## Verification

Use synthetic, original colored PNG/WebP sheets and generic manifests, never account/private artwork. Test path resolution with Linux home and `CODEX_HOME`, custom/legacy/cached catalog discovery and missing cache, malformed/oversized/symlink/traversal sources, races during snapshot, image bounds/indices and decoder unavailability. Assert portable schema 1/2 round-trips, frame ordering/indexing, fallback disclosure, duplicate names and cancellation, managed-copy persistence after removal of source, no silent selection, source export protection under an import/export race, and no non-TUI rendering/monitor timers. Run full tests, typecheck, `npm pack --dry-run`, and a bounded CLI-fixture Pi smoke test. If no real source is available for local smoke testing, report fixture-only validation instead of claiming installed-CLI compatibility; macOS/Windows and official desktop compatibility are expressly untested and out of scope.
