# Pi Pets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an original Pi-shaped animated companion that remains visible and reacts to activity in interactive Pi.

**Architecture:** Bundle selected frames from the user-provided ZIP; separate a pure event-to-animation state machine and an asset reader from the Pi widget/lifecycle adapter. Use Pi's image widget for supported terminals and its fallback for others. Start rendering only with a TUI session, and dispose all timers/widgets on shutdown.

**Tech Stack:** TypeScript, Node.js 22+, `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `tsx` + `node:test` for tests.

**Spec:** `docs/superpowers/specs/2026-10-02-pi-pets-design.md`

## Global Constraints

- Original supplied Pi mascot: coral `#F09082`, blue `#4D9ABF`, gold `#F1BE58`; preserve `Pi-export.zip` untouched and uncommitted.
- Bundle only required `frames/` transparent PNG assets; no runtime art generation, downloads, external models, or changes to Pi's prompts/tools.
- Persistent compact widget above editor; no keyboard focus. Text fallback when graphics are unavailable; no separate desktop window.
- Initialize/animate only in `session_start` when `ctx.mode === "tui"`; cleanup on `session_shutdown` and component disposal; print/JSON modes create no timers.
- Follow Pi's own graphics capability handling; no direct terminal escape writes. Do not assert interactive visual verification without a compatible terminal.

## Review Focus

- Tool calls overlap: a completed tool must not set idle while another is running (Task 2 test).
- A failed tool followed by `agent_end` must not incorrectly celebrate (Task 2 test).
- An agent run aborted after earlier successful tools must not jump (Task 2 test).
- Missing/corrupt PNG or ZIP path traversal must fail safely without loading unsafe assets (Task 1 tests).
- Reload/shutdown or toggling twice must leave no timers or stale widgets (Task 3 tests).

## File Map

- `package.json`, `tsconfig.json`: package entry, scripts, dev dependencies, type checking; Pi package manifest for extension discovery.
- `scripts/extract-assets.mjs`: allowlisted extraction from the supplied ZIP with path-safe output.
- `assets/<state>/<nn>.png`, `assets/manifest.json`: runtime PNGs and ordered frame manifest.
- `src/state.ts`: pure lifecycle/state transitions and frame stepping.
- `src/assets.ts`: safe frame loading/validation/caching, bounded text fallback.
- `src/widget.ts`: widget Image component and animation tick, no Pi event subscriptions.
- `index.ts`: Pi factory, command, lifecycle subscriptions and teardown.
- `test/*.test.ts`: each module's behavior, including mock TUI lifecycle.
- `README.md`, `.gitignore`: installation, capability behavior, licensing/provenance, ignored ZIP.

### Task 2: State Controller

**Files:** Create `src/state.ts`, `test/state.test.ts`.

**Interfaces:** Consumes `Animation` from `src/assets.ts`. Produces `PetController` with `handle(input: PetEvent, now: number): void`, `frame(now: number): { animation: Animation; index: number }`; `PetEvent = { type: "agent_start" | "tool_start" | "tool_end" | "prompt_start" | "prompt_end" | "settle"; error?: boolean; outcome?: "completed" | "aborted" | "error" }`. Controller keeps active tool count and error flag per run; transient states expire by timestamp, not independent timers. `settle` receives actual outcome from `agent_before_settle` and does not celebrate an errored run.

- [ ] **Step 1: Write failing state tests** — assert idle loops deterministically; `agent_start` selects running; prompt_start selects waiting and prompt_end resumes running; tool_end success briefly selects review but overlapping tools keep working; tool_end error selects failed; completed settle jumps only when no recorded error, aborted/error settle fails; new agent_start supersedes a previous transient; frame index wraps correctly and never becomes negative at `now=0`.
- [ ] **Step 2: Run `npm test -- --test-name-pattern='state'`** — expect FAIL.
- [ ] **Step 3: Implement `PetController`** — one monotonic timestamp-based transient (e.g. 800 ms for review and jump, 1200 ms for failed); fixed frame period around 160–240 ms, no wall-clock timers in state module. Final state idle after transients; an outstanding prompt keeps waiting.
- [ ] **Step 4: Run `npm test && npm run typecheck`** — PASS.
- [ ] **Step 5: Commit** — `git add src/state.ts test/state.test.ts && git commit -m 'feat: model pet activity and reactions'`.

### Task 3: Pi Widget and Lifecycle

**Files:** Create `src/widget.ts`, `index.ts`, `test/widget.test.ts`, `test/extension.test.ts`; expand `tsconfig.json` if needed.

**Interfaces:** Consumes `loadFrames`/`FrameLibrary` and `PetController`. Produces `createPetWidget(tui: TUI, theme: Theme, frames: FrameLibrary | null, controller: PetController): Component & { dispose(): void }` in `src/widget.ts`; `index.ts` exports Pi extension factory. Widget owns one timer at a modest refresh interval and replaces its current `Image` with a frame preserving Kitty image ID where available; component's `render(width)` clamps dimensions and returns bounded lines. `dispose()` clears the timer idempotently. Command `/pet` toggles visibility.

- [ ] **Step 1: Write failing widget/extension tests** — assert one timer only; render clamps narrow widths, text fallback with missing assets and unsupported capability, ticking requests render, dispose twice clears once; fake Pi API confirms start only in TUI, `/pet` toggles widget, lifecycle events map to controller, shutdown clears widget and timer, no setup in print mode.
- [ ] **Step 2: Run `npm test -- --test-name-pattern='widget|extension'`** — expect FAIL.
- [ ] **Step 3: Implement Pi integration** — use `ctx.ui.setWidget('pi-pet', factory, { placement: 'aboveEditor' })`, `ctx.ui.setWidget('pi-pet', undefined)` for cleanup, `agent_start`, tool execution, UI prompt, and `agent_before_settle` with `outcome` for result; no state change in `agent_end` that overrides settle. Guard loading failure and non-TUI. On session replacement and reload, disposal must not retain a previous session's widget. Use `Image`'s own terminal fallback; don't write to stdout.
- [ ] **Step 4: Run `npm test && npm run typecheck`** — PASS; check precise installed Pi event/widget signatures and correct any mock assumptions.
- [ ] **Step 5: Commit** — `git add index.ts src/widget.ts test/widget.test.ts test/extension.test.ts tsconfig.json && git commit -m 'feat: animate pet widget in Pi sessions'`.
